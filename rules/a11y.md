# Accessibility

ui-code-review has no accessibility rules of its own. The rules live in the **accessibility-framework**
plugin (v1.2.0+), which must be installed. The review runs its read-only area agents on the UI files in
scope and turns their findings into comments.

| Area | Agent (`subagent_type`) | Rule ID in comments |
|---|---|---|
| 1 Labels | `accessibility-framework:accessibility-labels` | `A11Y-LABELS` |
| 2 Alt / icons | `accessibility-framework:accessibility-alt` | `A11Y-ALT` |
| 3 ARIA | `accessibility-framework:accessibility-aria` | `A11Y-ARIA` |
| 4 Semantics | `accessibility-framework:accessibility-semantics` | `A11Y-SEMANTICS` |
| 5 Keyboard | `accessibility-framework:accessibility-keyboard` | `A11Y-KEYBOARD` |

## How the review uses them

- Run only the areas that match the changed markup (no form fields → skip Labels; no `<img>` / icons →
  skip Alt). Pass each agent the changed files and `Stack: Angular` or `Stack: ASP.NET MVC`.
- Give the agents the other files in the review as read-only context, so they confirm a finding
  before reporting it. Findings that are not defects, optional or unconfirmed go under `OutOfScope:`.
- Keep only findings whose `location` is on a line in `changedLines`. When `location` lists several
  lines, the comment goes on the first one that is changed.
- Drop any finding whose message says it is not a defect or unverified, or whose fix starts with
  "none" or "optional".
- Map each finding to a comment: `issue` + `fix`. Severity is **Warning**; when the agent sets
  `runtimeCheck: needed`, the comment says a keyboard / screen-reader check is still needed.
- Stylesheet accessibility (focus outline, hover, reduced motion) is part of AXIS: see the AXIS
  accessibility guide referenced from `axis.md`.
