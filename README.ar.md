# ui-code-review: شرح مبسط

## بتعمل إيه البلاجن دي؟

**ui-code-review** بلاجن لـ Claude Code بتعمل **مراجعة كود UI** للـ Pull Request (في Git) أو الـ Changeset (في TFVC) على سيرفر TFS / Azure DevOps بتاع الشركة. وبعد المراجعة بتكتب الملاحظات **كومنتات على السطور نفسها**، زي ما مراجع بشري بيعمل بالظبط.

بتراجع **السطور اللي اتغيرت بس** في ملفات الـ UI (`.html`, `.scss`, `.css`, `.ts`, `.cshtml`, `.js`)، على 3 مجموعات قواعد:

| المجموعة | كود القاعدة | بتشيك على إيه |
|---|---|---|
| **AXIS** | `R-xx` | تنظيم الـ SCSS/CSS وأسماء الكلاسات |
| **Localization** | `I18N-xx` | النصوص المكتوبة في الكود بدل الترجمة، والـ keys الناقصة، وإن ملفات العربي والإنجليزي ماشيين مع بعض |
| **Accessibility** | `A11Y-*` | سهولة الاستخدام لذوي الاحتياجات الخاصة (Angular و Razor) |

كل حاجة المراجعة محتاجاها موجودة جوه البلاجن نفسها.

## محتاجة إيه عشان تشتغل؟

- Windows PowerShell 5.1 و Claude Code.
- متغير بيئة اسمه `SONARTOOLKIT_TFS_PAT` فيه الـ Token بتاع TFS (نفس التوكن بتاع q-ai-quality-review). السكريبتات بتقراه من البيئة ومش بيتكتب في أي أمر.
- لو هتراجعي PR: لازم تشغليها من جوه نسخة الريبو اللي على جهازك، ويكون الـ remote اسمه `origin` وبيبدأ بـ `https://`.
- لو هتراجعي changeset: محتاجة رابط الـ TFVC collection، مثلًا `https://tfs25.alqemam.com/GCollection`.

مرة واحدة على الجهاز، من الفولدر اللي فيه `.claude-plugin/marketplace.json`:

## الاستخدام

بتكتبي أمر واحد:

</div>

```
/ui-code-review:review pr <id> [--dry-run]
/ui-code-review:review changeset <id> [--collection <url>] [--dry-run]
```

<div dir="rtl">

- `pr`: شغليه من جوه الريبو.
- `changeset`: الـ collection بييجي من `--collection`، ولو مش موجود من `UI_REVIEW_TFVC_COLLECTION`، ولو مش موجود هيسألك مرة واحدة.
- `--dry-run`: بيوريكي المعاينة ويقف من غير ما ينشر حاجة.

## بتشتغل إزاي؟ (5 خطوات)

</div>

```
1. تجهيز الملفات  →  2. اختيار المراجعين  →  3. المراجعة (بالتوازي)  →  4. الدمج  →  5. معاينة ← موافقة ← نشر
```

<div dir="rtl">

كل تشغيلة بتحط ملفات الشغل بتاعتها في فولدر لوحدها: `%TEMP%\ui-code-review\<pr|changeset>-<id>-<yyyyMMdd-HHmmss>\`. والفولدرات القديمة لنفس الـ PR أو الـ changeset اللي عدى عليها أكتر من 7 أيام بتتمسح أول ما تشغيلة جديدة تبدأ.

### مراجعة واحدة بس لكل PR أو changeset في نفس الوقت

الخطوة الأولى بتعمل قفل (lock) في `%TEMP%\ui-code-review\<pr|changeset>-<id>.lock`، والمراجعة بتشيله لما تخلص (`scripts/Release-ReviewLock.ps1`). لو حد شغّل مراجعة تانية لنفس الـ PR أو الـ changeset وهي لسه شغالة، التانية بتقف برسالة `REVIEW-LOCKED` وبتقول الأولى بدأت إمتى، بدل ما تكتب فوق نتايجها. ولو القفل عدى عليه أكتر من ساعتين، بيتعامل على إنه من مراجعة وقفت في النص، وبيتشال لوحده. ولو أحدث من كده، المراجعة بتسألك الأول، وبعدين تاخده بـ `-Force`.

### 1. تجهيز الملفات (`Get-ReviewTarget.ps1`)

- **PR:** بتسحب الـ PR من السيرفر، وتجيب الـ source والـ target branches، وتطلع الفرق بينهم.
- **Changeset:** بتقرا ملفات الـ changeset والنسخ القديمة بتاعتها من السيرفر.

بتاخد ملفات الـ UI وملفات الترجمة بس (ملفات `.json` جوه فولدر زي `i18n` أو `locales`، وملفات `.resx`)، وبتتجاهل الملفات المضغوطة (minified) و`.spec.ts` و`.d.ts` وأي حاجة جوه `node_modules` أو `dist` أو `bin` أو `obj`.

النتيجة: ملف `target.json` فيه كل ملف وأرقام السطور اللي اتغيرت فيه، وفولدر `files\` فيه المحتوى الجديد الكامل لكل ملف. وكمان كل ملفات الترجمة بتاعة المشروع (لحد 80 ملف) في فولدر `translations\`، عشان مراجع الـ Localization يقدر يتأكد إن كل key موجود في العربي والإنجليزي.

لو مفيش أي ملف UI اتغير بتقف، ولو الملفات أكتر من 40 بتسألك الأول تكمل ولا لأ.

### 2. اختيار المراجعين

| المراجع | بياخد إيه |
|---|---|
| `reviewer-axis` | كل ملفات الـ UI (قواعد الستايل لملفات `.scss` و`.css`، وقواعد أسماء الكلاسات لباقي الملفات) |
| `reviewer-i18n` | ملفات الـ markup والـ scripts، وملفات الترجمة اللي اتغيرت |
| مراجعين الـ Accessibility | ملفات الـ markup وملفات `.ts` بتاعة الكومبوننتات، حسب الفحص السريع |

مراجعين الـ Accessibility خمسة، وكل واحد منهم بيشتغل بس لو الملف فيه حاجة تخصه:

| المراجع | بيشتغل لو الملف فيه |
|---|---|
| Labels | `<input` أو `<select` أو `<textarea` أو `<label` أو `formControlName` أو `asp-for` |
| Alt | `<img` أو `<svg` أو أيقونات |
| ARIA | `aria-` أو `role=` أو `modal` أو `dialog` |
| Semantics | `(click)` أو `<table` أو `<ul` أو العناوين `<h1`..`<h6` أو `<form` |
| Keyboard | `tabindex` أو `(click)` أو `keydown` أو `modal` أو `dropdown` |

### 3. المراجعة بالتوازي

كل المراجعين (وهم AI agents) بيشتغلوا في نفس الوقت، وكلهم **قراءة بس** ومينفعش يعدلوا أي ملف. كل واحد منهم:

- بيراجع السطور اللي اتغيرت بس.
- بيطلع غلطات حقيقية محتاجة تتصلح بس، ويكون اتأكد منها بنفسه. لو الغلطة معتمدة على ملف تاني، بيقراه الأول.
- بيحدد سطر واحد بالظبط لكل ملاحظة.

### 4. دمج النتايج (`Merge-Findings.ps1`)

سكريبت بقواعد ثابتة بيجمع ردود كل المراجعين في ملف واحد `findings.json`، فنفس الردود دايمًا بتطلع نفس النتيجة:

- ملاحظات الـ Accessibility بتبقى `A11Y-<AREA>` بدرجة Warning.
- أي ملاحظة بتتشال (مع تحذير) لو: الملف مش في المراجعة، أو مفيهاش رقم سطر، أو بتقول إنها مش غلطة أو مش مؤكدة، أو الحل بتاعها بيبدأ بـ "none" أو "optional".
- الملاحظات المتكررة (نفس القاعدة والملف والسطر) بتتكتب مرة واحدة.

### 5. معاينة ثم موافقة ثم نشر (`Publish-Findings.ps1`)

- الأول بتشوفي **معاينة** لكل الكومنتات قبل ما أي حاجة تتنشر (`comments.json` و`report.md`).
- تقدري تمسحي كومنت أو تعدلي كلامه وتشوفي المعاينة تاني.
- **مفيش حاجة بتتنشر غير لما تقولي "أيوه"**.

مين بياخد كومنت:

- الملاحظات اللي على سطور اتغيرت بس.
- الـ Error دايمًا بياخد كومنت على السطر.
- الـ Warning بياخد كومنت لحد 15 كومنت، بيتختاروا حسب الأولوية: الـ Accessibility الأول، وبعدين الـ Localization، وبعدين AXIS. وبياخد ملاحظة واحدة من كل قاعدة بالدور، عشان قاعدة واحدة متكررة متاخدش كل الأماكن. والزيادة بتتكتب في الملخص بس.
- الـ Info بيظهر في الملخص بس.
- الملاحظات اللي على نفس السطر بتتجمع في كومنت واحد.

بتتنشر فين:

- **PR:** كومنت على كل سطر في الـ diff، وكومنت ملخص واحد.
- **Changeset:** كومنت على كل سطر وملخص على الـ changeset. ولو السيرفر رفض، بتكتب كومنت واحد فيه كل الملاحظات في الـ Discussion بتاع الـ Work Item المربوط بيه.

## ميزة ذكية: إعادة التشغيل

كل كومنت جواه "بصمة" مخفية (`<!-- ui-review:... -->`) متعمولة من القاعدة واسم الملف ونص السطر، مش من رقم السطر. يعني لو السطر اتنقل مكانه مش هيتعمل كومنت جديد. ولو شغلتيها تاني:

- مش هتكرر الكومنتات اللي اتكتبت قبل كده.
- في الـ PR، لو الغلطة اتصلحت، الكومنت بتاعها بيتعلم عليه **Fixed** لوحده. والكومنتات اللي حد قفلها قبل كده مبتتلمسش.
- الملخص بيتعدل في مكانه لو النتايج اتغيرت.

## مشاكل شائعة

| المشكلة | السبب والحل |
|---|---|
| `not a git repository` مع `pr` | شغلي المراجعة من جوه نسخة الريبو اللي على جهازك. |
| الـ Work Item مش موجود / 404 | الـ Work Item في collection تانية. حطي الصح في `--collection`. |
| `401 Unauthorized` على كومنتات الـ changeset | التوكن مش معاه صلاحية. المراجعة بتكتب في الـ Work Item بدل كده، ولو عايزة تكتبي على الـ changeset نفسه زودي صلاحيات التوكن. |
| AXIS اتخطت | فولدر `skills/axis-scss/docs` مش موجود. ثبتي البلاجن تاني من الباكدج الكاملة. |
| مراجع Accessibility اتخطى | ملفات `agents/accessibility-*.md` أو `references/` مش موجودة. ثبتي البلاجن تاني من الباكدج الكاملة. |
| `REVIEW-LOCKED` | فيه مراجعة تانية شغالة على نفس الـ PR أو الـ changeset. استني لما تخلص. ولو مش شغالة خلاص (الشباك اتقفل في نص المراجعة)، قولي للمراجعة كده وهي هتاخد القفل بـ `-Force`. |

## ملاحظات مهمة

- المراجعين AI، فممكن تشغيلتين على نفس الكود يطلعوا نتايج مختلفة شوية. عشان كده خطوة المعاينة مهمة.
- مشاكل الـ accessibility اللي معتمدة على تصرف الصفحة وهي شغالة (زي الـ focus والكيبورد) بيتكتب جنبها إنها محتاجة تتجرب بالكيبورد أو بالـ screen reader في الأبلكيشن نفسه.
