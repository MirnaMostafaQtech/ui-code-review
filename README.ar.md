# ui-code-review: شرح مبسط

## بتعمل إيه البلاجن دي؟

**ui-code-review** بلاجن لـ Claude Code بتعمل **مراجعة كود UI** للـ Pull Request (في Git) أو الـ Changeset (في TFVC) على سيرفر TFS / Azure DevOps بتاع الشركة. وبعد المراجعة بتكتب الملاحظات **كومنتات على السطور نفسها**، زي ما مراجع بشري بيعمل بالظبط.

بتراجع **السطور اللي اتغيرت بس** في ملفات الـ UI (`.html`, `.scss`, `.css`, `.ts`, `.cshtml`, `.js`)، على 5 مجموعات قواعد:

| المجموعة | كود القاعدة | بتشيك على إيه |
|---|---|---|
| **AXIS** | `R-xx` | تنظيم الـ SCSS/CSS وأسماء الكلاسات |
| **Localization** | `I18N-xx` | النصوص المكتوبة في الكود بدل الترجمة، والـ keys الناقصة، وإن ملفات العربي والإنجليزي ماشيين مع بعض |
| **Security** | `SEC-xx` | HTML متبني من بيانات، وتعطيل الحماية في Angular، و`Html.Raw` في Razor، وأسرار مكتوبة في الكود، و links مش آمنة |
| **Performance** | `PERF-xx` | حجم الصور وطريقة تحميلها، والخطوط، والفيديو، ومسارات الملفات |
| **Accessibility** | `A11Y-*` | سهولة الاستخدام لذوي الاحتياجات الخاصة (Angular و Razor) |

وكمان بتعمل **فحص للحل** (`FIX-xx`): بتقرا الـ Bug أو الـ User Story المربوطين بالـ PR، وبتشوف من الـ diff بتاع **كل** الملفات اللي اتغيرت هل التعديل فعلًا بيعمل المطلوب ولا لأ. التفاصيل تحت في "فحص الحل".

كل حاجة المراجعة محتاجاها موجودة جوه البلاجن نفسها.

## محتاجة إيه عشان تشتغل؟

- Node.js 18.3 أو أحدث و Claude Code. السكريبتات بتستخدم مكتبات Node الأساسية بس، فمفيش `npm install`.
- لو شهادة HTTPS بتاعة سيرفر TFS صادرة من جهة شهادات خاصة بالشركة وNode مش واثق فيها (الطلبات بتفشل بـ
  `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`)، صدّري شهادة الجهة دي كملف `.pem` وحطي مساره في `NODE_EXTRA_CA_CERTS`. ولو Node عندك 22.15 أو أحدث، ممكن بدل كده تحطي
  `NODE_OPTIONS=--use-system-ca`، فيثق في شهادات Windows زي ما كان PowerShell بيعمل.
- السكريبتات بتتصل بـ TFS مباشرة: Node مش بيستخدم إعدادات الـ proxy بتاعة Windows زي PowerShell، فلازم سيرفر TFS يكون متاح من غير proxy.
- متغير بيئة اسمه `SONARTOOLKIT_TFS_PAT` فيه الـ Token بتاع TFS (نفس التوكن بتاع q-ai-quality-review). السكريبتات بتقراه من البيئة ومش بيتكتب في أي أمر.
- لو هتراجعي PR: لازم تشغليها من جوه نسخة الريبو اللي على جهازك، ويكون الـ remote اسمه `origin` وبيبدأ بـ `https://`.
- لو هتراجعي changeset: محتاجة رابط الـ TFVC collection، مثلًا `https://tfs.example.com/DefaultCollection`.

## التثبيت

الريبو ده هو نفسه marketplace للبلاجن، واسمه `ui-review`. مرة واحدة على الجهاز، ضيفيه من GitHub على طول وثبّتي البلاجن:

</div>

```
claude plugin marketplace add MirnaMostafaQtech/ui-code-review
claude plugin install ui-code-review@ui-review
```

<div dir="rtl">

أو من نسخة الريبو اللي على جهازك: `claude plugin marketplace add <مسار الريبو>`، وبعدين نفس أمر التثبيت. وبعد كده اقفلي Claude Code وافتحيه. ونفس الأوامر شغالة من جوه Claude Code كـ `/plugin marketplace add ...` و `/plugin install ...`.

### التحديث

Claude Code بيشغّل نسخة من البلاجن اتعملت وقت التثبيت، مش الريبو نفسه. فأي تعديل مش بيوصلك غير لما تحدّثي:

</div>

```
claude plugin marketplace update ui-review
claude plugin update ui-code-review@ui-review
```

<div dir="rtl">

وبعدين اقفلي Claude Code وافتحيه. **ولما تعدلي في البلاجن، لازم تكبّري رقم `version` في `.claude-plugin/plugin.json`**، لأن التحديث مش بيثبّت حاجة لو رقم النسخة زي ما هو.

## الاستخدام

بتكتبي أمر واحد:

</div>

```
/ui-code-review:review pr <id> [--dry-run] [--no-fix-check] [--verify-runtime <url>] [--figma <frame url>]
/ui-code-review:review changeset <id> [--collection <url>] [--dry-run] [--no-fix-check] [--verify-runtime <url>] [--figma <frame url>]
```

<div dir="rtl">

- `pr`: شغليه من جوه الريبو.
- `changeset`: الـ collection بييجي من `--collection`، ولو مش موجود من `UI_REVIEW_TFVC_COLLECTION`، ولو مش موجود هيسألك مرة واحدة.
- `--dry-run`: بيوريكي المعاينة ويقف من غير ما ينشر حاجة.
- `--no-fix-check`: من غير فحص الحل.
- `--verify-runtime <url>`: بيجرّب في المتصفح الحالات اللي الكود لوحده مكفاش يحكم فيها، على التطبيق اللي إنتي مشغّلاه على `<url>`.
- `--figma <frame url>`: بيقارن الصفحة بفريم واحد من Figma، ولازم يبقى معاه `--verify-runtime`. ومن غيره، الريفيو عمره ما بيحكم على التصميم.

## فحص الحل

1. **التجميع:** بيقرا الـ work items المربوطة بالـ PR أو الـ changeset، وبياخد بس **Bug** و **User Story** (و Product Backlog Item و Requirement). الـ Task بيتساب.
   - كل work item بيتحفظ نص عادي في `workitems/<id>.md`.
   - أي باسورد أو توكن أو OTP مكتوب فيه بيتشال ويتكتب مكانه `[redacted]`.
   - وبيتعمل `full.diff` لكل الملفات اللي اتغيرت، مش الـ UI بس، لحد 3000 سطر.
2. **الحكم:** الـ `reviewer-fix` بيدي كل work item حالة من دول: `Fixed` أو `Partial` أو `SymptomOnly` أو `NotAddressed` أو `Unclear`، ومع كل شرط بيكتب `ملف:سطر` كدليل. والكومنتات على السطور بتتعمل بس لو فيه مشكلة واضحة على سطر اتغير:
   - `FIX-01`: شرط مش متنفذ.
   - `FIX-02`: التعديل بيخبّي العَرَض بدل ما يحل السبب.
   - `FIX-03`: مفيش test للحالة.
3. **التجربة (اختياري بـ `--verify-runtime`):** للحالات اللي الكود مكفاش يحكم فيها، بيمشي الخطوات في المتصفح على التطبيق اللي إنتي مشغّلاه.
   - **قبل ما تبدئي:** شغّلي التطبيق على branch الـ PR، واعملي login بنفسك. هو عمره ما بيعمل build ولا بيشغّل server ولا بيكتب باسورد.
   - **إزاي بيبقى سريع:** بيخطط الأول من غير متصفح: الـ route، والـ selector من السطر اللي اتغير، والقيمة المطلوبة. وبعدين كل صفحة بتاخد دورة واحدة: navigate، ويستنى العنصر، وسطر JavaScript واحد زي `getComputedStyle(el).direction`. بيغيّر اللغة مرة واحدة بس، ومفيش screenshots للصفحة كلها.
   - **الحدود:** بحد أقصى 8 خطوات في المتصفح لكل work item، ومش بيحفظ أو يمسح أو يبعت أي بيانات غير لما توافقي. والملخص بيكتب عدد الخطوات والثواني اللي أخدها.
4. **Figma (اختياري بـ `--figma <frame url>`):** المطابقة مع التصميم اختيارية. من غير الـ flag، أي bug بيقول "مش مطابق للتصميم" بيتحكم عليه باللي التعديل عمله في الشاشة دي، وغياب التصميم عمره ما بيخلّي الحكم `Unclear`. ومع الـ flag:
   - بيقرا الفريم مرة واحدة (`get_metadata`، و`get_variable_defs` لو متاح)، ويربط الـ layers بالـ selectors.
   - بيقرا نفس القيم من الصفحة الشغالة في دورة واحدة لكل لغة: المقاسات بفرق ±2px، والألوان، والخطوط وأحجامها.
   - لو **مطابق**، شرط التصميم بيتعلّم متنفذ. لو **مش مطابق**، بيتعلّم مش متنفذ، و `Fixed` بيبقى `Partial`، وبيكتب القيم المختلفة (ومعاها `FIX-01` على سطر الـ SCSS لو السطر ده اتغير).
   - اللينك لازم يكون لـ **فريم واحد**: كليك يمين على الفريم واختاري **Copy link to selection**. لينك الصفحة كلها أكبر من إنه يتقري.
   - لو الـ work item فيه لينك Figma وإنتي مش حاطة الـ flag، الريفيو بيقولك بس إن اللينك موجود.
5. **التقرير:** كومنت الملخص بيبدأ بقسم "Fix check" فيه حالة كل work item، وجدول بالشروط، ونتيجة المتصفح ونتيجة Figma.

لو مفيش Bug أو Story مربوط، أو الـ work items مااتقرتش، فحص الحل بيتساب بسطر واحد بيقول ليه، ومراجعة الـ UI بتكمل عادي.

**التكلفة التقريبية لكل PR:**
- **فحص الكود:** حوالي 1–2 دقيقة و 30–80 ألف توكن.
- **التجربة في المتصفح:** حوالي دقيقة و 20–40 ألف توكن لكل work item، لو الفحص ينفع يتعمل من الـ DOM. ده تقدير، ولسه ماتقاسش على تطبيق شغال.

## بتشتغل إزاي؟ (5 خطوات)

</div>

```
1. تجهيز الملفات  →  2. اختيار المراجعين  →  3. المراجعة (بالتوازي)  →  4. الدمج  →  5. معاينة ← موافقة ← نشر
```

<div dir="rtl">

كل تشغيلة بتحط ملفات الشغل بتاعتها في فولدر لوحدها: `%TEMP%\ui-code-review\<pr|changeset>-<id>-<yyyyMMdd-HHmmss>\`. والفولدرات القديمة لنفس الـ PR أو الـ changeset اللي عدى عليها أكتر من 7 أيام بتتمسح أول ما تشغيلة جديدة تبدأ.

### مراجعة واحدة بس لكل PR أو changeset في نفس الوقت

الخطوة الأولى بتعمل قفل (lock) في `%TEMP%\ui-code-review\<pr|changeset>-<id>.lock`، والمراجعة بتشيله لما تخلص (`scripts/release-review-lock.js`). لو حد شغّل مراجعة تانية لنفس الـ PR أو الـ changeset وهي لسه شغالة، التانية بتقف برسالة `REVIEW-LOCKED` وبتقول الأولى بدأت إمتى، بدل ما تكتب فوق نتايجها. ولو القفل عدى عليه أكتر من ساعتين، بيتعامل على إنه من مراجعة وقفت في النص، وبيتشال لوحده. ولو أحدث من كده، المراجعة بتسألك الأول، وبعدين تاخده بـ `--force`.

### 1. تجهيز الملفات (`get-review-target.js`)

- **PR:** بتسحب الـ PR من السيرفر، وتجيب الـ source والـ target branches، وتطلع الفرق بينهم.
- **Changeset:** بتقرا ملفات الـ changeset والنسخ القديمة بتاعتها من السيرفر.

بتاخد ملفات الـ UI وملفات الترجمة بس (ملفات `.json` جوه فولدر زي `i18n` أو `locales` أو `Resources`، وملفات الترجمة المكتوبة TypeScript زي `*.i18n.ts`، وملفات Angular `.xlf`، وملفات .NET `.resx` و`.po`)، وبتتجاهل الملفات المضغوطة (minified) و`.spec.ts` و`.d.ts` وأي حاجة جوه `node_modules` أو `dist` أو `bin` أو `obj`.

النتيجة: ملف `target.json` فيه كل ملف وأرقام السطور اللي اتغيرت فيه، وفولدر `files\` فيه المحتوى الجديد الكامل لكل ملف. وكمان كل ملفات الترجمة بتاعة المشروع (لحد 80 ملف) في فولدر `translations\`، عشان مراجع الـ Localization يقدر يتأكد إن كل key موجود في العربي والإنجليزي. وكمان قايمة بكل الصور والخطوط والفيديوهات اللي اتضافت أو اتغيرت وحجم كل واحد، عشان مراجع الـ Performance.

لو مفيش أي ملف UI اتغير بتقف، ولو الملفات أكتر من 40 بتسألك الأول تكمل ولا لأ.

### 2. اختيار المراجعين

| المراجع | بياخد إيه |
|---|---|
| `reviewer-axis` | كل ملفات الـ UI (قواعد الستايل لملفات `.scss` و`.css`، وقواعد أسماء الكلاسات لباقي الملفات) |
| `reviewer-i18n` | ملفات الـ markup والـ scripts، وملفات الترجمة اللي اتغيرت |
| `reviewer-security` | ملفات الـ markup والـ scripts اللي الفحص السريع لقى فيها حاجة تخصه (`innerHTML` و`Html.Raw` و`localStorage` و`target="_blank"` و`token` وغيرهم) |
| `reviewer-performance` | ملفات الـ markup والستايل والكومبوننتات اللي الفحص السريع لقى فيها حاجة تخصه (`<img` و`<video` و`@font-face` و`url(` وغيرهم) |
| مراجعين الـ Accessibility | ملفات الـ markup وملفات `.ts` بتاعة الكومبوننتات، حسب الفحص السريع |

مراجعين الـ Accessibility خمسة، وكل واحد منهم بيشتغل بس لو الملف فيه حاجة تخصه:

| المراجع | بيشتغل لو الملف فيه |
|---|---|
| Labels | `<input` أو `<select` أو `<textarea` أو `<label` أو `formControlName` أو `asp-for` |
| Alt | `<img` أو `<svg` أو أيقونات |
| ARIA | `aria-` أو `role=` أو `modal` أو `dialog` |
| Semantics | `(click)` أو `<table` أو `<ul` أو العناوين `<h1`..`<h6` أو `<form` |
| Keyboard | `tabindex` أو `(click)` أو `keydown` أو `modal` أو `dropdown` |

### 3. المراجعة بالتوازي

كل المراجعين (وهم AI agents) بيشتغلوا في نفس الوقت، وكلهم **قراءة بس** ومينفعش يعدلوا أي ملف. كل واحد منهم:

- بيراجع السطور اللي اتغيرت بس.
- بيطلع غلطات حقيقية محتاجة تتصلح بس، ويكون اتأكد منها بنفسه. لو الغلطة معتمدة على ملف تاني، بيقراه الأول.
- بيحدد سطر واحد بالظبط لكل ملاحظة.

الرسالة اللي بتتبعت لكل مراجع قصيرة: فيها مكان ملف `target.json` وأسماء الملفات اللي هيراجعها بس. والمراجع بيقرا بنفسه من `target.json` محتوى كل ملف والسطور اللي اتغيرت وملفات الترجمة والصور، فمفيش بيانات بتتكرر في كل رسالة.

### 4. دمج النتايج (`merge-findings.js`)

السكريبت بياخد `--agent <name>=<agentId>` لكل مراجع اشتغل، ويقرا رد كل مراجع زي ما هو من الـ log اللي Claude Code بيحفظه لكل subagent (`~/.claude/projects/<project>/<session>/subagents/agent-<id>.jsonl`)، ويحفظه في `reviews\<name>.txt`. يعني محدش بيعيد كتابة الردود. ولو الـ id بتاع مراجع تاني، أو المراجع لسه ما خلصش، السكريبت بيرفض. شكل الـ log ده بتاع Claude Code ومش واجهة رسمية، فلو السكريبت ما عرفش يقرا رد، بيقف ويقول اسمه، والرد ده بيتحفظ في `reviews\<name>.txt` باليد.

وبعدها بيجمع ردود كل المراجعين بقواعد ثابتة في ملف واحد `findings.json`، فنفس الردود دايمًا بتطلع نفس النتيجة:

- ملاحظات الـ Accessibility بتبقى `A11Y-<AREA>` بدرجة Warning.
- أي ملاحظة بتتشال (مع تحذير) لو: الملف مش في المراجعة، أو مفيهاش رقم سطر، أو بتقول إنها مش غلطة أو مش مؤكدة، أو الحل بتاعها بيبدأ بـ "none" أو "optional".
- الملاحظات المتكررة (نفس القاعدة والملف والسطر) بتتكتب مرة واحدة.

### 5. معاينة ثم موافقة ثم نشر (`publish-findings.js`)

- الأول بتشوفي **معاينة** لكل الكومنتات قبل ما أي حاجة تتنشر (`comments.json` و`report.md`).
- تقدري تمسحي كومنت أو تعدلي كلامه وتشوفي المعاينة تاني.
- **مفيش حاجة بتتنشر غير لما تقولي "أيوه"**.

مين بياخد كومنت:

- الملاحظات اللي على سطور اتغيرت بس.
- الـ Error دايمًا بياخد كومنت على السطر.
- الـ Warning بياخد كومنت لحد 15 كومنت، بيتختاروا حسب الأولوية: الـ Security الأول، وبعدين الـ Accessibility، وبعدين الـ Localization، وبعدين AXIS، وبعدين الـ Performance. وبياخد ملاحظة واحدة من كل قاعدة بالدور، عشان قاعدة واحدة متكررة متاخدش كل الأماكن. والزيادة بتتكتب في الملخص بس.
- الـ Info بيظهر في الملخص بس.
- الملاحظات اللي على نفس السطر بتتجمع في كومنت واحد.

بتتنشر فين:

- **PR:** كومنت على كل سطر في الـ diff، وكومنت ملخص واحد.
- **Changeset:** كومنت على كل سطر وملخص على الـ changeset. ولو السيرفر رفض، بتكتب كومنت واحد فيه كل الملاحظات في الـ Discussion بتاع الـ Work Item المربوط بيه.

## ميزة ذكية: إعادة التشغيل

كل كومنت جواه "بصمة" مخفية (`<!-- ui-review:... -->`) متعمولة من القاعدة واسم الملف ونص السطر، مش من رقم السطر. يعني لو السطر اتنقل مكانه مش هيتعمل كومنت جديد. ولو شغلتيها تاني:

- مش هتكرر الكومنتات اللي اتكتبت قبل كده.
- في الـ PR، الكومنت بيتعلم عليه **Fixed** لوحده بس لما الغلطة متطلعش تاني **و** السطر اللي كانت عليه يكون اتغير أو اتمسح (كل كومنت فيه كمان علامة مخفية للسطر `<!-- ui-review-line:... -->`). لو المراجعة متكررتش الملاحظة بس السطر زي ما هو، الكومنت بيفضل مفتوح، لأن المراجعين مش بيطلعوا نفس النتيجة كل مرة. والكومنتات اللي حد قفلها قبل كده، والكومنتات اللي اتكتبت قبل نسخة 0.3.4 (من غير علامة السطر)، مبتتلمسش.
- الملخص بيتعدل في مكانه لو النتايج اتغيرت.

## مشاكل شائعة

| المشكلة | السبب والحل |
|---|---|
| `not a git repository` مع `pr` | شغلي المراجعة من جوه نسخة الريبو اللي على جهازك. |
| الـ Work Item مش موجود / 404 | الـ Work Item في collection تانية. حطي الصح في `--collection`. |
| `401 Unauthorized` على كومنتات الـ changeset | التوكن مش معاه صلاحية. المراجعة بتكتب في الـ Work Item بدل كده، ولو عايزة تكتبي على الـ changeset نفسه زودي صلاحيات التوكن. |
| AXIS اتخطت | فولدر `skills/axis-scss/docs` مش موجود. ثبتي البلاجن تاني من الباكدج الكاملة. |
| مراجع Accessibility اتخطى | ملفات `agents/accessibility-*.md` أو `references/` مش موجودة. ثبتي البلاجن تاني من الباكدج الكاملة. |
| الكومنتات مش بتتنشر على الـ PR | بصي على الـ output بتاع خطوة النشر. لو فيه **`401` أو `403`**: التوكن لازم يكون فيه صلاحية **Code (Read & Write)**، وحسابك لازم يكون مسموحله يكتب على الـ Pull Requests في الريبو ده، فاعملي توكن جديد بالصلاحية دي. لو مكتوب **`already there`**: الكومنتات اتنشرت في تشغيلة قبل كده، ومش هتتكرر. لو مكتوب **`Dry run: nothing posted`**: التشغيلة كانت بـ `--dry-run`، أو مااتقالش "أيوه" بعد المعاينة، فشغليها تاني ووافقي. لو **`Comment on <file>:<line> failed`** على سطور معينة بس: الـ PR اتضافله commits بعد ما المراجعة بدأت، فشغلي المراجعة تاني. |
| `REVIEW-LOCKED` | فيه مراجعة تانية شغالة على نفس الـ PR أو الـ changeset. استني لما تخلص. ولو مش شغالة خلاص (الشباك اتقفل في نص المراجعة)، قولي للمراجعة كده وهي هتاخد القفل بـ `--force`. |
